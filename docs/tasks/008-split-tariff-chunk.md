# 008. Не грузить справочник тарифов на страницах, которым он не нужен

## Цель

Приёмка волны 1 показала: чанк `dist/assets/TariffDateNote-*.js` весит около 1,6 МБ (весь справочник комиссий WB), потому что `src/app/components/tools/TariffDateNote.tsx` импортирует `tariffRegistry` целиком ради даты. Этот чанк подтягивается на всех страницах `/tools/*`, включая `/tools/drr`, которая тарифы не использует. Мобильному пользователю это лишние мегабайты.

## Что сделать

1. Вынести метаданные (`updatedAt`, источник, `formatTariffDate`) в маленький модуль без данных тарифов, например `src/app/config/tariffMeta.ts`; `tariffRegistry` продолжает его реэкспортировать, внешний API и существующие импорты не ломаются.
2. `TariffDateNote` и `ToolPage` импортируют только маленький модуль.
3. Данные комиссий и складов загружаются только там, где нужны расчёты: страницы WB-инструментов могут импортировать их статически, но `/tools`, `/tools/drr` и главная не должны тянуть этот чанк.
4. Тест: дата в `TariffDateNote` совпадает с `tariffRegistry.meta.updatedAt`.
5. Заодно добавить в `package.json` скрипт `"preview": "vite preview"` (его нет, а в инструкциях приёмки он упоминается).

## Критерии готовности

- `npm run check` проходит.
- В `dist/tools/drr/index.html` и в загружаемом им JS нет ссылки на чанк со справочником тарифов; размер JS, нужный для `/tools/drr`, не превышает 400 КБ без сжатия.
- Даты актуальности тарифов на `/calculator` и страницах инструментов не изменились.
- `npm run preview` запускает сервер на 4173.

## Не делать

- Не менять формулы и значения тарифов, не трогать `webview-safe` разделение бандлов калькулятора.
