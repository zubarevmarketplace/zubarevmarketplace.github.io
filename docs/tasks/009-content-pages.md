# 009. Реестр контентных страниц, раздел /reference и шаблон страницы справочника

## Цель

Волна 2 добавляет справочники: комиссии по категориям, склады, словарь, чек-листы, шаблоны. Это не инструменты, а контентные страницы с произвольными адресами, и их будут сотни. Нужен второй реестр, который маршрутизация, prerender и sitemap понимают так же, как реестр инструментов, плюс общий шаблон страницы справочника и хаб `/reference`.

## Что сделать

1. **Реестр контентных страниц** `src/app/content/registry.ts`. Тип `ContentPageDefinition`: `path` (абсолютный, например `/reference/glossary/drr`), `title`, `h1`, `description`, `section` (`'reference' | 'templates' | 'checklists'`), `updatedAt`, `load: () => Promise<{ default: ComponentType<{ page: ContentPageDefinition }> }>`, `data?: unknown` (произвольные данные страницы, чтобы один компонент обслуживал сотни страниц), `related?: string[]` (пути), `breadcrumbs: { label: string; path: string }[]`. Экспорт `contentPages: ContentPageDefinition[]` собирается из модулей-поставщиков: `src/app/content/<section>/pages.ts` экспортирует массив; реестр их конкатенирует. В этой задаче поставщик один: хаб `/reference`.
2. **Маршрутизация, prerender, sitemap**: `resolveRoute` в `src/app/tools/routes.ts` (или новый `src/app/routes.ts`) находит контентную страницу по `path`. `scripts/prerender.ts` рендерит все пути из обоих реестров. `src/app/tools/sitemap.ts` включает контентные страницы с `lastmod`. `src/app/seo/metadata.ts` отдаёт метаданные и для контентных страниц, включая JSON-LD `BreadcrumbList`.
3. **Шаблон** `src/app/components/content/ContentPage.tsx`: хлебные крошки, H1, вводный абзац, `children`, дата обновления, блок «Смотрите также» из `related` (ссылки на инструменты и справочники, скрывать несуществующие), короткий CTA на разбор. Общий `Layout`.
4. **Хаб** `/reference` (`src/app/content/reference/ReferenceIndexPage.tsx`): H1 «Справочники для продавцов Wildberries и Ozon», карточки разделов, которые появятся в волне 2: комиссии WB, склады WB, словарь, лимиты полей карточки, чек-листы, шаблоны. Карточки на страницы, которых ещё нет, не показывать (правило AGENTS.md); сейчас хаб может быть почти пустым, это нормально. В `Header` ссылка «Справочники» на `/reference`, `currentPage: 'reference'`.
5. **Хелпер slug**: `src/app/lib/slugify.ts` с транслитерацией кириллицы в латиницу (ГОСТ-подобная, без диакритики: «Спортивный товар» → `sportivnyj-tovar`), только `[a-z0-9-]`, без двойных дефисов. Тест на 5 примеров и на уникальность после нормализации.
6. Тесты: реестр без дублей путей, все пути начинаются с `/`, `related` указывают на существующие пути или slug инструментов; `resolveRoute('/reference')` возвращает контентную страницу; sitemap содержит `/reference`.

## Критерии готовности

- `npm run check` проходит.
- `dist/reference/index.html` содержит свой `<title>`, H1 и JSON-LD `BreadcrumbList`.
- Ссылка «Справочники» в шапке на десктопе и в мобильном меню.
- Добавление нового справочника требует только модуля-поставщика в `src/app/content/<section>/pages.ts`.

## Не делать

- Не переделывать реестр инструментов и существующие страницы инструментов.
- Не писать содержимое справочников в этой задаче.
