# Приёмка волны

Цель: за минимум токенов убедиться, что выполненные задачи реально работают, и зафиксировать итог. Не переделывать работу Codex: мелкие правки допустимы, крупные замечания уходят обратно в очередь новой задачей.

## Шаги

1. Прочитай `docs/BACKLOG.md`. Выпиши задачи со статусом `done`, у которых ещё нет записи в `docs/runs/acceptance.md`, и задачи со статусом `blocked`.
2. Для каждой `done`-задачи прочитай только раздел «Итог» и последний «Отчёт исполнителя» в `docs/runs/<id>.md`. Не читай потоковые логи в `.codex-work/`.
3. Запусти `npm run check` один раз для всей волны. Если не проходит, волна не принимается: запиши ошибку и остановись.
4. Для каждой новой страницы из задач (адреса из критериев готовности):
   - проверь, что `dist/<путь>/index.html` существует и содержит `<h1` с текстом и `<title>` страницы (команда `grep` по файлу, без чтения целиком);
   - проверь, что адрес есть в `dist/sitemap.xml`;
   - открой страницу через `npm run preview` в браузере на ширине 375 и 1280, сделай по одному скриншоту, убедись, что результат виден без действий и нет горизонтального скролла.
5. Для задач с расчётами выполни один ручной пример из спецификации (значения по умолчанию) и сравни с ожиданием из тестов. Если расходится, это замечание.
6. Для `blocked`-задач прочитай последнее ревью в `docs/runs/<id>.md` и ветку `codex/blocked-<id>`. Реши: вернуть в `todo` с уточнением спецификации, разбить на две задачи или закрыть. Запиши решение.
7. Запиши результат в `docs/runs/acceptance.md`: дата, список задач, статус «принята / замечания / отклонена», по одной строке на замечание. Замечания, требующие кода, оформи новыми строками в `docs/BACKLOG.md` со статусом `todo` и коротким файлом спецификации в `docs/tasks/`.
8. Закоммить `docs/runs/acceptance.md` и изменения очереди. Пользователю: три-пять строк итога по-русски.

## Чего не делать

- Не читать `.codex-work/` и потоковые логи.
- Не переписывать страницы ради стиля.
- Не менять правила в AGENTS.md без просьбы пользователя.
