# AGENTS.md — правила для Codex в репозитории zubarevlab.ru

Этот файл читает Codex перед каждой задачей. Claude здесь архитектор: пишет ТЗ в `docs/tasks/`, Codex реализует. Раннер `scripts/codex/run-queue.ps1` запускает задачи по очереди из `docs/BACKLOG.md`, проверяет сборку, делает коммит и пуш.

## Что это за проект

Публичный сайт zubarevlab.ru: лендинг услуг аналитика маркетплейсов и бесплатные онлайн-инструменты для продавцов Wildberries и Ozon. Цель: много полезных страниц под поисковый спрос, каждая с рабочим инструментом, и мягкая продажа платных разборов. Все расчёты выполняются в браузере, сервера нет.

## Стек и команды

- Vite 6, React 18, TypeScript, Tailwind 4, компоненты shadcn/Radix в `src/app/components/ui`. Пакет `react-router` установлен, но маршрутизация сейчас ручная в `src/main.tsx`.
- Сборка: `npm run build`. Проверка целиком: `npm run check` (сборка плюс тесты, появится после задачи 001). Тесты: vitest.
- Хостинг: GitHub Pages. Пуш в `main` запускает `.github/workflows/deploy.yml`, который собирает `dist` и публикует. Файл `public/CNAME` привязывает домен.
- Тарифы WB: `data/raw/*.xlsx` → `npm run generate:wb-tariffs` → `src/calculator/data/commissionTariffs.json` и `src/calculator/config/warehouseTariffs.ts`. Общие константы в `src/app/config/tariffs.ts`. Логика расчёта в `src/app/lib/calculateUnitEconomics.ts`.
- Действующий калькулятор: `src/app/pages/WbCalculatorPage.tsx`, адреса `/calculator` и `/tools/wb-calculator`.

## Жёсткие правила

1. Репозиторий публичный. Никаких токенов, ключей, паролей, `.env`, личных данных и финансовых выгрузок. Если задача требует секрет, остановись и напиши об этом в отчёте.
2. Не запускай `git commit`, `git push`, `git reset`, `git checkout` на другие ветки. Коммитит и пушит раннер.
3. Не удаляй и не ломай существующие страницы: главная `/` и `/calculator` должны работать после каждой задачи.
4. Не добавляй платные сервисы, внешние API с ключами и серверный код. Сайт статический.
5. Не меняй `public/CNAME`, `.github/workflows/deploy.yml`, счётчики Метрики и Clarity в `index.html`, верификационные мета-теги.
6. Не добавляй тяжёлые зависимости без необходимости. Для расчётов и UI хватает того, что есть.
7. `npm run check` обязан проходить в конце задачи. Если что-то не проходит и починить нельзя в рамках задачи, напиши об этом в отчёте, не выключай проверку.
8. Не трать время на документацию сверх того, что просит ТЗ. README не нужен для каждой фичи.

## Стандарты кода

- TypeScript строго, без `any` там, где можно описать тип.
- Все тексты интерфейса на русском языке. Денежные суммы форматируй через `src/app/lib/formatters.ts`.
- Визуальный стиль: тёмная тема как на существующих страницах, Tailwind-классы, компоненты из `src/app/components/ui`. Mobile first: страница должна быть пригодна на ширине 375px без горизонтального скролла.
- Расчётная логика живёт в чистых функциях в `src/app/lib/` или `src/app/tools/<slug>/calc.ts` и покрыта тестами vitest. Компоненты только отображают.
- Все инструменты берут тарифы из единого справочника и показывают дату актуальности тарифов из одного места.
- Код должен быть пригоден для рендера в статический HTML: `window`, `document`, `localStorage` только внутри `useEffect` или с проверкой `typeof window !== 'undefined'`.

## Стандарт страницы инструмента

Каждый инструмент — отдельная страница с собственным адресом вида `/tools/<slug>`. На странице сверху вниз:

1. H1 с названием инструмента и ключевой фразой запроса.
2. Два-три предложения, кому и зачем нужен расчёт.
3. Сам инструмент. Результат виден сразу, без регистрации и без ввода контактов. Разумные значения по умолчанию, чтобы результат был виден при первом открытии.
4. Блок «Как считается»: формула словами и ключевые допущения.
5. Блок «Частые вопросы»: 3–5 вопросов с ответами, продублированные в JSON-LD `FAQPage`.
6. Дата актуальности тарифов.
7. Ссылки на 2–4 смежных инструмента.
8. Короткий блок с предложением платного разбора и ссылкой на `/#formats` или `/#contacts`. Без агрессии: одна фраза и кнопка.

У страницы должны быть свои `<title>`, `meta description`, `canonical`, Open Graph, и адрес должен попадать в `sitemap.xml`.
